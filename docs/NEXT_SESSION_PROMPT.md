أنت وكيل هندسي يعمل داخل مستودع حقيقي لنظام إدارة مستشفى (HMS) عربي/إنجليزي، RTL أولًا، مبني بـ TypeScript. مهمتك في هذه الجلسة، بهذا الترتيب الصارم:

## 5) قواعد معمارية إلزامية (مخالفتها = إعادة عمل)

- **ترحيل جديد فقط**: لا تعدّل ترحيلًا مُطبَّقًا (فحص checksum سيرفض). التالي `018_*.sql`.
- كل جدول جديد: `ENABLE` + `FORCE ROW LEVEL SECURITY`، سياسة `tenant_isolation` على `facility_id`، و`GRANT` مناسب لدور `hms_app` (لا `DELETE` للسجلات السريرية).
- كل مسار: `requireAuth` + `requirePermission` + `parse(zod)` + `withTenant` أو `withTenantAudited` (الأخير لكل تعديل، مع `action/entityType/entityId/patientId/detail/ip`).
- **فصل المهام**: من ينفّذ لا يعتمد (مختبر، تعقيم، دم، عدوى، حالات). فرضه في API **وفي trigger** حيث أمكن.
- **المنطق على الخادم**: أي حساب (SOFA، صلاحية، توافق دم، أهداف تغذية، جودة) يُحسب في API، لا في الواجهة.
- **السجلات السريرية ملحقة**: لا تعديل صامت بعد الاعتماد؛ التصحيح بإصدار/إلغاء موثّق.
- **الأموال والمخزون**: `Idempotency-Key` ومنع التكرار على مستوى قاعدة البيانات.
- **لا `any` جديد بلا سبب**، ولا TODO معلّق بلا تذكرة في `docs/`.
- كل قاعدة جديدة تحتاج **اختبارًا إيجابيًا واختبارًا سلبيًا** (محاولة تجاوز تُرفض)، ويفضل اختبار trigger مباشر عبر `db.asRole('hms_app', …)`.

## 6) العيوب والمشاكل المعروفة — أصلحها كلها ووثّق كل إصلاح

### P0 — واجهة (تحجب الاستخدام اليومي)
1. **ملف واحد ضخم**: `apps/web/src/App.tsx` = 2777 سطرًا و20 صفحة. قسّمه إلى `src/pages/*`، `src/components/*`، `src/hooks/*`، `src/lib/*` مع إبقاء السلوك كما هو (أثبت ذلك ببناء ناجح وفحص كل صفحة).
2. **لا توجيه URL**: الصفحة في `useState` فقط، فتحديث المتصفح يعيد المستخدم للوحة القيادة، ولا يوجد رابط مباشر أو زر رجوع. المطلوب: hash routing (`#/patients`، `#/cssd`…) يحترم الصلاحيات، ويحفظ آخر صفحة لكل مستخدم.
3. **8 استخدامات لـ `window.prompt`** لطلب أسباب سريرية (تخطي مهمة، إغلاق خطة رعاية، إلغاء عملية، إيقاف تغذية، سحب دورة تعقيم، إنهاء عزل، تأكيد/استبعاد حالة عدوى). هذه تجربة سيئة وتفقد النص عند الخطأ. استبدلها بمكوّن **ReasonDialog** عربي: عنوان، شرح للعواقب، حد أدنى للأحرف مع عدّاد، تعطيل الزر حتى الصلاحية، وإظهار خطأ الخادم داخل النافذة. أضف **ConfirmDialog** للإجراءات غير القابلة للتراجع (لا يوجد أي `window.confirm` حاليًا).
4. **حالات التحميل/الفراغ/الخطأ غير موحدة**: توجد جداول تعرض فراغًا بلا شرح، وأخطاء تظهر كنص خام. أضف `Skeleton`, `EmptyState`, `ErrorState` مع زر إعادة المحاولة، و**ErrorBoundary** أعلى الشجرة حتى لا تبيضّ الصفحة.
5. **لا إشعارات نجاح/فشل موحّدة**: استخدم `Toast`/`aria-live` بدل نصوص متناثرة.

### P0 — سلوك/بيانات
6. **تأكيد حد المعدل**: أي دفعات فحص HTTP متكررة تُصادف 429 على تسجيل الدخول. أعد تشغيل الخادم بقاعدة جديدة بين الدفعات، ولا ترفع الحد لأجل الاختبار.
7. **أرقام التوثيق تتقادم**: أي تغيير في عدد الاختبارات/الجداول/المسارات يجب أن يُحدّث `README.md` و`docs/TEST_PLAN.md` و`docs/DATA_MODEL.md` في نفس الـcommit.
8. **`.github/` غير متتبع عن قصد** — لا تضفه ولا تحذفه.
9. **`GET /api/nutrition/patients/:id`** يُعاد تحميله بعد كل إجراء؛ تحقق من عدم وجود استعلامات N+1 أو إعادة جلب غير ضرورية في لوحة التغذية وبقية اللوحات.
10. افحص `TODO|FIXME|HACK` و`as any` غير المبرر والمسارات غير المستخدمة، وأصلح أو وثّق.

### P1 — واجهة/تجربة
11. **صفر `aria-*`** في التطبيق: لا skip link، لا `aria-live`، لا تسميات لحقول/أزرار أيقونية، لا حبس تركيز (focus trap) في النوافذ، لا إدارة تركيز بعد الإغلاق.
12. **الجداول غير صالحة للجوال**: `min-w-[900px..1100px]` مع تمرير أفقي. أضف نمط بطاقات للجوال (أو أعمدة قابلة للطي) لكل الجداول ذات الأهمية: المرضى، الحزم، الدورات، الطلبات، الفواتير.
13. **لوحة القيادة فقيرة**: 8 أرقام + جدولان، بلا اتجاه زمني ولا رسم. أضف مؤشرات زمنية (7/30 يومًا)، توزيع إشغال الأسرّة، وتنبيهات حرجة قابلة للنقر تنقلك للصفحة المعنية.
14. **لا بحث شامل**: أضف بحثًا في الترويسة (MRN / اسم / رقم مستند) مع نتائج مصنّفة واختصار لوحة مفاتيح.
15. **لا حفظ لتفضيلات**: اللغة (عربي/إنجليزي)، الصفحة الأخيرة، عرض الجداول، كثافة الواجهة. حقل `preferred_language` موجود في المستخدم.
16. **لا طباعة مخصصة**: أنماط `@media print` للفاتورة/التقرير/ملخص المريض، مع ترويسة منشأة وتاريخ ورقم مستند.
17. **الهوية بصرية ضعيفة**: شعار/أيقونة/`favicon`، ألوان حالة موحدة (نجاح/تحذير/خطر/معلومة)، واتساق المسافات والخطوط.
18. **صفحة «حالة الوحدات»** تعرض الحالة فقط؛ اجعلها تعرض *ما ينقص* لكل موديول جزئي وما هو غير منفذ، مع روابط.
19. **التحديث التلقائي**: لوحات التعقيم/الطوارئ/الطابور/المختبر تحتاج تحديثًا دوريًا (polling 20–30 ثانية قابلًا للإيقاف) ومؤشر «آخر تحديث».
20. **لا E2E**: Playwright غير متوفر ولا يمكن تنزيل متصفحات. أنشئ `scripts/ui-smoke.mjs` يعمل عبر `fetch`: يسجّل الدخول بكل دور، يجلب بيانات كل صفحة يراها، ويتحقق من الشكل والحقول الحرجة، ويطبع ملخصًا. شغّله في كل جلسة ووثّق نتيجته بصدق.

### P2 — تقنية/أمنية
21. لا SAST/DAST/pen-test ولا `npm audit` آلي. شغّل `npm audit --omit=dev`، عالج ما يمكن، وسجّل الباقي في `docs/SECURITY.md` بصدق.
22. لا اختبارات أداء. أضف سكربت قياس بسيط (زمن استجابة 20 مسارًا رئيسيًا) وسجّل النتائج كما هي.

## 7) خطة تحسين الواجهات (نفّذها كوحدة واحدة متماسكة)

**الهدف:** واجهة سريرية عربية RTL سريعة وواضحة، تُستخدم فعليًا على شاشة 1366×768 وعلى جوال، بلا أزرار شكلية.

### 7.1 نظام تصميم ومكونات
أنشئ `apps/web/src/components/` بهذه المكونات (استخدم Tailwind والأنماط الموجودة في `styles.css`، لا مكتبة UI جديدة إلا بمبرر ADR):
`Button` (primary/ghost/danger/busy) · `Badge` (خريطة حالات موحدة) · `Card` · `PageHeader` (عنوان + وصف + إجراءات) · `StatCard` · `DataTable` (أعمدة معرّفة، فرز، تمرير، نمط بطاقات للجوال، حالة فراغ) · `Modal`/`Sheet` (RTL، focus trap، ESC) · `ReasonDialog` · `ConfirmDialog` · `Field`/`Input`/`Select`/`Textarea` (label إلزامي + خطأ inline) · `Tabs` · `Toast` · `Skeleton` · `EmptyState` · `ErrorState` · `Pagination` · `SearchInput` (debounce) · `Breadcrumbs` · `StatusTimeline` (لدورات التعقيم/الزيارة).

### 7.2 الهيكل والتوجيه
- `Layout` فيه: شريط جانبي على الشاشات ≥ lg (قابل للطي، مجموعات: سريري/تشغيلي/مالي/إدارة)، وقائمة سفلية/درج على الجوال.
- ترويسة: بحث شامل، المنشأة النشطة (تبديل إن وُجدت عضوية متعددة)، المستخدم/الدور، الإشعارات، خروج.
- Hash routing مع:
  - `#/page` و`#/page/:id` عند الحاجة (فتح سجل مريض/حزمة/طلب مباشرة).
  - احترام الصلاحيات: مسار غير مسموح ⇒ صفحة `Forbidden` واضحة لا شاشة فارغة.
  - مسار مجهول ⇒ `NotFound`.
  - زر الرجوع يعمل، والتحديث يحافظ على الصفحة.

### 7.3 الجودة البصرية والوصول
- RTL كامل، `dir="rtl"`، أرقام وتواريخ عبر `Intl`، عملة SAR.
- تباين AA، أحجام لمس ≥ 40px، حلقات تركيز ظاهرة، `aria-live` للرسائل، `aria-label` لكل زر أيقوني، `role="dialog"` و`aria-modal` للنوافذ.
- لا تعتمد على اللون وحده لمعنى الحالة (أضف نصًا/رمزًا).
- سكيلتون بدل «جارٍ التحميل…» النصية.

### 7.4 النماذج
- تحقق فوري + تعطيل ذكي + رسائل عربية مرتبطة بالحقل.
- معاينة ملخص قبل الإجراءات السريرية الحساسة (صرف دم، اعتماد دورة، إغلاق زيارة).
- الحفاظ على المسودة عند فشل الطلب.
- لا تفقد بيانات المستخدم عند خطأ شبكة.

### 7.5 الأداء
- AbortController عند تغيير الصفحة، تجنّب إعادة الجلب غير الضرورية، cache للقوائم المرجعية (أقسام/أطقم/أطباء)، وتقسيم الحزمة (`lazy` للصفحات الثقيلة).

### 7.6 اختبار الواجهة بلا متصفح
`scripts/ui-smoke.mjs`:
1. يسجّل الدخول لكل حساب في القسم 1.
2. يفتح المسارات الظاهرة لكل دور ويجلب بياناتها.
3. يتحقق من: 200، حقول مطلوبة، صفر أخطاء 5xx، وصفر `undefined` في حقول العرض الحساسة.
4. يطبع جدولًا: الدور / الصفحة / الحالة / الزمن.
5. يُشغّل مرة على الخادم المحلي ومرة على رابط Vercel (مع 401 متوقع للمسارات المحمية قبل الدخول).

## 8) الموديولات التالية (بالترتيب، موديول كامل في كل دفعة)

لكل موديول أسلّم: ترحيل جديد + جداول RLS + triggers الحماية + مسارات API + صلاحيات/أدوار + بيانات تجريبية + اختبارات (إيجابي/سلبي/trigger) + صفحة واجهة كاملة + تحديث `MODULE_STATUS` و`README` و`docs/API` و`DATA_MODEL` و`TEST_PLAN` و`USER_GUIDE` + حدود معلنة.

1. **الموارد البشرية (HR)**: موظفون، أقسام، مسميات، تعاقدات، رخص مهنية وتواريخ انتهاء، ورديات، إجازات، تقييم أداء بسيط، ربط المستخدم بالطبيب/التمريض. حدود: لا رواتب/تأمينات/GOSI حقيقية.
2. **المخازن والمشتريات**: أصناف عامة بجانب الأدوية، مستودعات، حد إعادة الطلب، طلبات شراء → أوامر شراء → استلام → فاتورة مورد، حركات مخزون غير قابلة للتعديل. حدود: لا ربط بموردين حقيقيين ولا مناقصات.
3. **الأصول والصيانة**: سجل أصول (أجهزة طبية/تقنية)، موقع/مسؤول، صيانة وقائية دورية، أوامر عمل تصحيحية، تعطل يمنع الاستخدام، تاريخ معايرة. حدود: لا IoT ولا تكامل مع الشركات.
4. **الجودة والامتثال**: مؤشرات جودة، تدقيقات، ملاحظات عدم مطابقة، إجراءات تصحيحية (CAPA) بدورة حياة، حوادث سلامة، سياسات بإصدارات واعتماد. حدود: لا ادعاء اعتماد JCI/CBAHI.
5. **المستندات والأرشفة**: مستندات مرتبطة بالمريض/الموظف/المنشأة، تصنيف، إصدارات، توقيع/اعتماد، صلاحية اطلاع، وبحث. حدود: لا OCR ولا تخزين سحابي — تخزين محلي مع مسار مرفق إن أمكن.
6. **المالية**: دفتر أستاذ مبسط، مراكز تكلفة، سندات قبض/صرف، تسوية، وتقارير مالية. حدود: لا ضرائب/زكاة محسوبة آليًا ولا ربط بمحاسبة خارجية.
7. **تحسين التأمين/الأشعة/البوابة/التكامل** كما في القسم 4، مع حدود واضحة (لا DICOM فعلي، لا بوابة دفع حقيقية، FHIR جزئي فقط).
