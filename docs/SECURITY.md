# الأمن والخصوصية — Threat Model وضوابط

> هذا المستند يوضح **ما طُبّق فعليًا وما لم يُطبّق**. لا يُعد ادعاءً بامتثال قانوني أو اعتماد تنظيمي.

## 1) نموذج الثقة

| العنصر | الثقة |
|---|---|
| المتصفح / React SPA | **غير موثوق** — كل تحقق على الخادم |
| اتصال الشبكة | TLS على الـ proxy (وثائق النشر) |
| API (Fastify) | موثوق، لكن يفترض أن أي إدخال قد يكون خبيثًا |
| قاعدة البيانات | مصدر الحقيقة + طبقة إنفاذ RLS |
| المشرف على قاعدة البيانات | عالي الخطورة (يمكنه تجاوز RLS؛ يُمنع من قراءة بيانات الإنتاج إلا بإجراء موثق) |

## 2) التحليل: التهديدات ← الضوابط ← المتبقي

| # | التهديد | الضابط المنفذ | متبقي |
|---|---|---|---|
| T1 | استيلاء على حساب | Argon2id، قفل بعد 5 محاولات، Rate limit، MFA (TOTP+rموز استرداد)، إبطال جلسات | لا SSO مؤسسي ولا ربط بالهوية الوطنية |
| T2 | CSRF | رأس `x-csrf-token` لكل تعديل + مقارنة Origin/Host + SameSite=Lax | لا اختبار DAST آلي |
| T3 | XSS | React escaping، CSP (`script-src 'self'`)، لا `dangerouslySetInnerHTML` | CSP تسمح `style-src 'unsafe-inline'` لضرورة المكوّنات |
| T4 | حقن SQL | استعلامات معّلمة فقط، لا تركيب نصوص من مدخلات، Zod | لا SAST مستقل |
| T5 | تسريب بيانات بين المنشآت | RLS مفعّل + `FORCE ROW LEVEL SECURITY` + `SET LOCAL ROLE` داخل كل معاملة + اختبارات | مشرف DB يمكنه `BYPASSRLS` |
| T6 | اطلاع غير مصرح على ملف مريض | RBAC + ABAC (علاقة علاجية) + break-glass مسبب + سجل في `patient_access_log` | مراجعة break-glass دورية يدوية (لا workflow آلي للمراجعة) |
| T7 | انتحال مستخدم في اعتماد نتيجة | منع `resulted_by = verified_by` على الخادم | لا توقيع إلكتروني معتمد (PKI/معتمد وطني) |
| T8 | تكرار العمليات المالية | `Idempotency-Key` + فهرس فريد على مرجع البند + `FOR UPDATE` على الفاتورة | لا تكامل مع بوابة دفع |
| T9 | التلاعب بسجل التدقيق | سلسلة Hash + trigger يمنع UPDATE/DELETE + REVOKE + `hash_version` | لا إرسال خارجي (WORM/SIEM) — موصى به للإنتاج |
| T10 | افتراض كلمة المرور الأولية | `must_change_password` مفروض، تدوير عند التغيير، إبطال الجلسات | لا انتهاء صلاحية دوري لكلمات المرور |
| T11 | تسريب بيانات في السجلات | تنقيح `cookie/authorization/x-csrf-token` في Pino، عدم تسجيل payloads | لوجات التطبيق محلية بلا تجميع مركزي |
| T12 | حذف/تعديل سجل طبي معتمد | `clinical_notes` و`lab_result_amendments` و`stock_movements` append-only؛ تصحيح النتائج بسجل تعديل مسبب | بقية الجداول قابلة للتحديث (بتدقيق) |
| T13 | استنزاف/إساءة API | Rate limit عام + خاص بالدخول، حد لحجم الجسم 1MB | لا WAF موثق |
| T14 | سرقة المفاتيح | مفاتيح من متغيرات بيئة إلزامية في الإنتاج (لا قيم افتراضية)، ولا مفاتيح في الواجهة | لا KMS/Vault مدمج — مطلوب في الإنتاج |
| T15 | استعادة بيانات تالفة | نسخ مشفّرة + سكربت استعادة + فحص سلسلة التدقيق | **لم تُنفذ تجربة استعادة فعلية** |

## 3) التشفير

- **النقل:** TLS 1.2/1.3 على الـ proxy؛ HSTS في الإنتاج.
- **السكون:** AES-256-GCM للحقول: الهوية الوطنية، الجوال، العنوان، جوال المرافق، رقم البوليصة، سر TOTP. AAD = `table.column:rowId`.
- **البحث:** فهرس أعمى HMAC-SHA256 (دقيق) للهوية/البوليصة، والاسم يُبحث كنص (لا تشفير) — **مقايضة مقصودة** لتمكين البحث؛ يلزم تقييم مخاطر.
- **كلمات المرور:** Argon2id (m=19456 KiB, t=2, p=1).
- **الجلسات:** الرمز يُخزَّن كـ HMAC فقط، Cookie httpOnly + Secure (إنتاج) + SameSite=Lax.

## 4) إدارة الأسرار والدوران

| السر | المصدر | الدوران |
|---|---|---|
| `SESSION_SECRET` | env/KMS | 90 يومًا (يُبطل كل الجلسات) |
| `ENCRYPTION_KEY` | env/KMS | موصى به: تشفير مغلّف (envelope) بمفتاح رئيسي في KMS؛ التدوير يحتاج إعادة تشفير تدريجية |
| `SEARCH_HASH_KEY` | env/KMS | يعطّل البحث بالهوية مؤقتًا عند الدوران |
| `DATABASE_URL` | env | 180 يومًا |

**لا** تُحفظ أي أسرار في Git؛ `.env` مستثنى، والاختبارات تُولّد مفاتيح عشوائية.

## 5) PDPL والتنظيم (السعودية) — تقييم مبدئي غير قانوني

- **مبادئ مطبقة تقنيًا:** تقليل البيانات، تحديد الغرض (صلاحية لكل عملية)، سجل وصول لكل قراءة ملف، تقييد المشاركة، تصحيح موثق، تشفير.
- **غير مكتمل:** سياسة احتفاظ/حذف تلقائية، بوابة حقوق الأفراد (وصول/تصحيح/سحب موافقة) بشكل كامل، اتفاقيات معالجة البيانات، تقييم أثر (DPIA) رسمي، تسجيل لدى الجهة المختصة.
- **خلاصة:** النظام **مصمم بوعي بالخصوصية**، لكن **لا يمكن القول إنه متوافق مع PDPL** أو أنه حاصل على أي اعتماد. يلزم: مراجعة قانونية، DPIA، اختبار اختراق مستقل، واعتماد من الجهات الصحية المختصة قبل الإنتاج.

## 6) الاستجابة للحوادث (Runbook مختصر)

1. **اكتشاف**: تنبيه على `auth.login` الفاشل المتكرر، `patient.break_glass`، فشل تحقق سلسلة التدقيق، معدل 429 غير طبيعي.
2. **احتواء**: تعطيل الحساب/إبطال الجلسات (`/api/admin/sessions/:id/revoke`)، تدوير المفاتيح المتأثرة.
3. **تحليل**: `/api/audit?actorUserId=…` و`/api/patient-access-log` و`/api/audit/verify` لتحديد نطاق الأثر.
4. **إشعار**: حسب المتطلبات النظامية (الجهة المختصة والأفراد) — قرار قانوني.
5. **تحسين**: إضافة اختبار انحدار يمنع تكرار السبب.

## 7) أهداف الاستعادة (مقترحة، غير مختبرة)

| المقياس | الهدف | كيف |
|---|---|---|
| RPO | ≤ 15 دقيقة | WAL archiving + نسخ WAL إلى تخزين منفصل |
| RTO | ≤ 4 ساعات | استعادة PITR على عقدة بديلة + إعادة توجيه الـ proxy |
| احتفاظ النسخ | 30 يومًا يوميًا + شهرية 12 شهرًا | سياسة `backup.sh` + تخزين كائنات |
| اختبار الاستعادة | شهريًا | `ops/restore.sh` + فحص سلسلة التدقيق |

**لا تُعتبر هذه الأهداف محققة حتى تُنفَّذ تجربة استعادة فعلية موثقة.**
